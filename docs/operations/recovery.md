# Резервное копирование и восстановление Company Brain

## Резервная копия

Для учения используйте отдельный профиль с синтетическими данными. Создайте документ с двумя подтверждёнными ревизиями и вложением. Задайте ACL, которые разрешают чтение одной тестовой учётной записи и запрещают другой. До копирования прочитайте документ и вложение от имени первой записи и зафиксируйте отказ для второй. Сохраните идентификаторы ревизий, SHA-256 вложения и время подтверждения последней записи в UTC.

Остановите все процессы, которые пишут в исходный профиль, и дождитесь завершения начатых операций. Возобновите запись после завершения `backup`. Пауза нужна для согласованного среза обеих баз, очереди ревью и вложений.

```python
from brain.operations.recovery import backup

result = backup(source_dir, archive_path)
print(result)
```

`backup` копирует `knowledge.db` и `audit.db` через SQLite backup API. ZIP также содержит `review.json`, обычные файлы из `attachments/` и `manifest.json` с SHA-256 файлов. Ревизии и ACL сохраняются в базе целиком. Симлинки, `ready.json` и параметры запуска профиля в архив не входят. Сохраните `result["archive_sha256"]` и `result["files"]` в протоколе отдельно от ZIP.

## Восстановление

Назначьте отсутствующий или пустой каталог для отдельного профиля. Запрещено подменять активный `data_dir`. Настройте отдельный запуск и проверьте, что его `data_dir` указывает на новый каталог.

В начале восстановления зафиксируйте `time.monotonic()` для измерения RTO. Сверьте SHA-256 полученного ZIP с хешем из отдельного протокола. Передайте сохранённый хеш и путь к ZIP внешней утилите проверки. При несовпадении остановитесь.

```sh
printf '%s  %s\n' "$EXPECTED_SHA256" "$ARCHIVE_PATH" | shasum -a 256 -c
```

```python
from brain.operations.recovery import restore

result = restore(archive_path, target_dir)
print(result)
```

`restore` проверяет манифест, допустимость путей, SHA-256 и `PRAGMA integrity_check` баз до публикации каталога. Сверьте `result["files"]` с протоколом копирования. Запустите профиль на `target_dir`. Когда он сообщит о готовности, снимите второе показание монотонных часов. Разность показаний в секундах составляет RTO до готового профиля. `result["rto_seconds"]` измеряет только вызов `restore`.

## Протокол учения

Повторите чтение того же документа и вложения через восстановленный профиль с обеими учётными записями. Сверьте обе ревизии, SHA-256 вложения и исходы проверки ACL с исходным профилем. Зафиксируйте фактические результаты в протоколе.

- Укажите идентификатор учения, время остановки записи, исходный и восстановленный каталоги.
- Запишите ожидаемый и проверенный SHA-256 ZIP, хеши файлов после копирования и восстановления и исход проверки целостности баз.
- Для RPO запишите идентификатор и время в UTC последней известной подтверждённой записи исходного профиля и последней подтверждённой записи, найденной в восстановленном профиле. Укажите разность в секундах и перечислите подтверждённые записи, которых нет в восстановленном профиле. Если исходная последняя запись найдена и сверка подтверждённых записей не выявила потерь, укажите RPO 0 с. Если одного из времён нет, отметьте RPO как неизмеренный.
- Для RTO запишите показания монотонных часов в начале восстановления и при готовности профиля, их разность в секундах и отдельно `rto_seconds` из `restore`.
- Запишите идентификаторы проверенных ревизий, хеш вложения и фактические исходы чтения для обеих учётных записей до и после восстановления. Учение успешно, если данные совпали, разрешённый доступ сохранился, а запрещённый завершился отказом.
