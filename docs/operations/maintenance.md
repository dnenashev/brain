# Гигиена и обслуживание базы знаний

## Перед записью

Вызывайте `lint_before_write` с идентификатором проекта, доступными автору ссылками `readable_refs` и лимитом `max_bytes` для одной записи. Записывайте карточку только при `ok=True`. Тело должно содержать текст, а его размер считается в байтах UTF-8. Список `sources` должен содержать хотя бы одну уникальную ссылку, и каждая ссылка должна быть доступна автору.

| Код | Действие оператора |
| --- | --- |
| `scope` | Проверьте проект карточки и контекст записи. |
| `invalid_body` | Укажите непустой текст, который можно закодировать в UTF-8. |
| `quota` | Сократите тело до лимита записи. |
| `invalid_sources` | Укажите непустой список ссылок без повторов. |
| `unreadable_source` | Проверьте доступ к источнику или укажите доступную ссылку. |

## Пересмотр и архив

Стройте `maintenance_plan` по снимку инвентаря проекта. Передайте время расчёта `now`, закреплённые ссылки `protected_refs`, лимит числа действующих карточек `max_active` и лимит их суммарного объёма `max_bytes`. Объём рассчитывается по `body_bytes`. Архивные карточки не расходуют квоты действующих карточек.

Срок пересмотра действующей карточки составляет 90 дней с `updated_at`. Если для проекта установлен другой срок, передайте его в `review_after_days`. Передайте позиции из `review` указанным владельцам. Закреплённые карточки также подлежат пересмотру.

Сверьте `archive` с актуальными закреплениями перед применением. При изменении инвентаря или закреплений пересчитайте план. План предлагает незакреплённые действующие карточки в порядке от самых старых до выполнения обеих квот. При `quota_met=False` предложенного архива недостаточно. Передайте дефицит владельцу проекта для пересмотра лимитов или закреплений и пересчитайте план после решения.

Передайте утверждённый план в `apply_archive`. Функция передаёт владельцу хранилища только предложенные ссылки в порядке плана. Хранилище переводит карточки в архив с сохранением URI и истории. При обращении по старой ссылке разрешайте исходный URI через сохранённые ревизии. Если URI указывает на конкретную ревизию, возвращайте её с учётом действующих правил доступа. Проверьте разрешение старых ссылок и чтение действующих карточек после применения.

## Нагрузочный прогон

Используйте 1 000 синтетических действующих карточек по 256 байт с разными `updated_at` и сохранёнными ревизиями. Закрепите две самые старые карточки, у которых истёк срок пересмотра. Каждый сценарий начинайте с исходного снимка.

| `max_active` | `max_bytes` | Ожидаемый результат |
| --- | --- | --- |
| 800 | 179 200 | Предложены 300 самых старых незакреплённых карточек. Остаются 700 карточек общим объёмом 179 200 байт. |
| 800 | 230 400 | Предложены 200 самых старых незакреплённых карточек. Остаются 800 карточек общим объёмом 204 800 байт. |
| 800 | 511 | `quota_met=False`. Две закреплённые карточки занимают 512 байт и отсутствуют в `archive`. |

Сверьте, что `review` включает обе просроченные закреплённые карточки с их владельцами. Примените первый план к тестовому хранилищу и сравните полученные им ссылки и их порядок с `archive`. Разрешите исходные ссылки на сохранённые ревизии архивированных карточек и сравните их содержимое со снимком. Сравните URI, состояния и тела всех оставшихся действующих карточек со снимком. Зафиксируйте коммит кандидата и результат прогона.
