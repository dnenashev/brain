# Новое требование к верхней границе таймаута

<a id="timeout-boundary"></a>
## Правило REG01

Запрошенный таймаут `300000` мс входит в допустимый диапазон. Для исходного значения `5000` мс проверка `verify_timeout_patch` должна вернуть `effective_timeout_ms: 300000` и `exception: null`.

| Запрошено, мс | Ожидаемый результат |
| ---: | --- |
| 0 | `invalid_input` |
| 299999 | Эффективный таймаут `299999` мс |
| 300000 | Эффективный таймаут `300000` мс, без исключения |
| 300001 | `invalid_input` |

Текущее значение по умолчанию и его утверждённая версия описаны в [текущем правиле разработки](../../docs/current/development.md#approved-timeout).

Ожидаемые значения заданы оператором в задаче `CB13-R2` и опубликованы в сценарии `REG01`. Для подтверждения независимый оператор сверяет все четыре результата и связывает свидетельство проверки с точным SHA кандидата. [Набор сценариев пилота](./pilot.v1.json)
